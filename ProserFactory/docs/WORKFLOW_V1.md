# Multi-workflow Book Factory v1

ProserFactory runs six workflow types on one durable background platform.
The types are `full_book`, `quality_review`, `improve_quality`,
`guided_improve`, `editorial_optimize`, and `revision_campaign_analysis`.
The API process validates ownership and queues work.
Book-scoped admission uses only the canonical ID returned by that ownership
lookup. Its HTTP deadline covers queue acceptance, not workflow execution. The
`proser-worker` service owns background execution under a separate renewable
workflow lease and absolute lifetime, so agent or browser disconnects do not
stop a run.

Editorial Optimize is checkpoint-free. It skips risky, disputed, stale,
or unverifiable edits and fails on unrecoverable integrity errors.
[Editorial engine](EDITORIAL_ENGINE.md)

Every run stores its source and result `ManuscriptRevision`, task graph, immutable artifacts, checkpoints, events, heartbeat, attempts, and parent/child links. Persisted intermediate phases resume after worker restarts, and an orphaned running row can be safely re-enqueued when no job is active. Execution attempts and orphan recoveries are lifetime counters and never reset; a separate current-delivery counter resets only at an explicit resume or approved human boundary, never during orphan recovery. Status responses expose all three values plus the configured delivery maximum. A malformed or context-incompatible model terminal response is never interpreted as success. Queue retries and recoveries are bounded, and exhausted work pauses with its failure reason.

Plain prose and structured workflow inference require `finish_reason: stop`. `length` is a typed truncation outcome; prose receives at most two continuation segments and each must repeat a validated overlap before it can be joined. `content_filter` becomes review-required/blocked, while `tool_calls` is accepted only by an agent tool loop. Valid terminal outcomes do not affect provider circuit health; provider failures, protocol failures, truncations, policy rejections, and content filters have separate telemetry counters. Prose operations are admitted by idempotent authenticated POST and persist a user-scoped receipt in Redis before inference begins. A separate manuscript-free cursor subscription carries JSON frames whose cursors are allocated atomically with event admission. Every worker frame verifies running state, the expected lease owner, unexpired lease and absolute lifetime, and no cancellation before it receives a cursor. Tokens and artifacts are provisional until a fenced terminal Lua transition verifies the current worker lease, applies cancellation precedence, promotes the artifact, removes active indexes, and writes the matching terminal replay event. Terminal states are immutable. Redis provides shared byte-bounded replay, separate per-attempt pending intervals/running leases/absolute lifetime deadlines, cancellation state, quotas, and cross-instance discovery; heartbeats refresh only the running lease. Claiming removes or terminalizes stale queue and running-index entries before enforcing concurrency and reports stale-lease recovery counts and latency through operation metrics. The final artifact has longer independent retention, while failed, cancelled, and expired operations discard provisional artifacts. An initially expired cursor receives HTTP 409 before SSE headers; expiration after subscription begins emits `replay_error`. Errors contain only a bounded public code/message and correlation ID, while complete exceptions remain in server logs.

Quality Review reads the exact source revision and writes only `QualityReviewRun` and `QualityFinding` records. Book scope covers every planned scene and performs separate chapter, act, and book passes. Narrow scopes stop at the requested level: scene reviews one scene, chapter reviews its scenes plus the chapter, and act reviews its scenes, chapters, and act. Completed scope tasks are reused after worker recovery instead of being reviewed twice. Every critic scope receives the authoritative character codex; full-book coverage also verifies canonical names and aliases across all prose. Review rounds from different models remain independent and comparable. Small-model evidence is normalized across straight/curly quotes and explicit ellipses; unsupported critical/high labels are conservatively downgraded when the quoted evidence is absent or the proposed repair is demonstrably localized.

Clients reconnect through `GET /api/books/:bookId/workflows`, which returns durable top-level runs with their child summaries. Status includes resource-version counters so polling clients reload checkpoints, artifacts, and publication state only when those resources change. Active checkpoint status contains only a bounded summary and artifact references; full proposal JSON requires an explicit `GET /api/workflows/:runId/checkpoints/:checkpointId` and is paged with `offset` and `limit`. Book findings are fetched through the paginated `GET /api/books/:bookId/findings` aggregate with state, model, severity, and scope filters instead of one request per review. No browser or agent session owns workflow progress.

Improve Quality revalidates evidence and groups compatible findings for the same scene into one coherent, dependency-aware revision instead of repeatedly rewriting that scene. It applies only localized edits within the safe-change envelope, captures a new revision, and only then marks each addressed finding implemented. Approved cross-scope advice targets only scenes containing its exact evidence; vague advice never becomes an implicit whole-book rewrite. The authoritative character codex is included in revision prompts and approval proposals, and a deterministic relationship guard escalates newly introduced gender or kinship contradictions. Guided relationship reconciliation uses bounded exact sentence replacements with a gender/kinship token whitelist instead of regenerating whole scenes. Rejected scene proposals are skipped on resume, and final changed scopes are re-derived from immutable source/current snapshots so worker restarts cannot lose the audit trail. Targeted verification is stored independently as pending, passed, or failed; a no-op editor response never counts as implementation. Structural, canon, chronology, POV, tense, large, conflicting, or cross-chapter work requires a checkpoint. Guided Improve follows the same mutation policy without requiring review findings.

Full Book creates architecture, codex characters and arcs, style bible, reconciled budgets, scene contracts, narrative ledgers, concurrently generated blinded candidates, prose, and nested editorial workflows. Empty or undersized critic revisions cannot replace a usable draft. The final package is gated separately from human approval and contains Markdown, EPUB, DOCX, HTML, metadata, and cover-specification files.

Revision snapshots hash manuscript and codex content rather than update timestamps. `POST /api/books/:bookId/revisions/:revisionId/rollback` restores a compatible prose/codex snapshot and creates a new descendant revision, preserving both the abandoned branch and per-finding implementation history. Structural membership changes require a dedicated structural rollback instead of being guessed silently.

Operators use `/api/workflows/:runId`, `/events`, `/checkpoints`, and `/artifacts` for inspection. Only Proser-owned Redis keys beginning with the configured BullMQ prefix and the `book-workflow-v1` queue name may be cleared during a reset.
