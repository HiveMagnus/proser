# Book Factory

The desktop `/workflows` surface is a thin authenticated client for ProserFactory workflow v1. It offers four independent launch actions: Full Book, Quality Review, Improve Quality, and Guided Improve.

Full Book progress includes its nested review, improvement, and verification runs. Review history remains grouped by model, rubric, source revision, and finding state. The finding ledger filters across model, severity, scope, implementation/verification state, waiver, and staleness without merging model opinions. Checkpoint actions are explicit author decisions; closing the page does not stop background execution.

The revision panel shows immutable ancestry, word counts, changed scopes, and compatible restore points. Restoring an older point requires browser confirmation and creates a new descendant revision; it never deletes the intervening history.

All browser requests use relative `/api/*` URLs and the existing Next.js proxy. The shared client immediately rejects pre-aborted calls, applies a 30-second default timeout, caller cancellation, and bounded JSON reads; the proxy independently applies endpoint-specific timeouts and response-size limits. The proxy requires a session for every route except the explicit public `GET /api/readiness` probe, strips upstream cookies and authentication challenges, and rejects redirects instead of exposing an internal destination. Publication artifacts require a known bounded size and allowed media type, then stream through without whole-file buffering. Their 15-second header timeout becomes a renewable 30-second idle-progress timeout after headers arrive, so total transfer duration is not the deadline.

Prose SSE is transactional at the browser boundary. The hook stores an explicit-state receipt with the idempotency key and normalized request, creates the operation through authenticated JSON POST, reconciles an uncertain response by the exact user-scoped key, and receives a durable receipt before it opens EventSource. The subscription URL contains only operation ID, cursor, and replay limit. Each JSON frame carries the Factory operation ID and monotonic cursor; after interruption, the hook reconnects using the last accepted cursor. A late POST receipt is cancelled only after explicit supersession or user cancellation; navigation, unmount, and stop-watching retain it visibly as detached background work. Reload recovery uses the exact-key active-or-terminal lookup for every receipt and reconnects the newest active request. Completed work is fetched from the authoritative artifact endpoint, verified against its SHA-256, and retained in the Completed Generation inbox; failed and cancelled outcomes remain visible until dismissed. Global reconciliation pauses while hidden or offline, applies capped jittered backoff after failures, and coordinates tabs with a browser lock and `BroadcastChannel`. “Stop tracking” closes EventSource and leaves Factory work running; “Cancel generation” calls Factory’s terminal cancellation endpoint. The proxy passes authenticated event streams through incrementally with MIME, byte, and idle-time validation. The hook bounds provisional bytes, words, frames, and duration from the requested word target, then verifies metadata word count and final SHA-256 before exposing text. Malformed/replayed frames, expired replay windows, typed truncation, filtering, limit violations, and hash mismatches discard the temporary buffer. Public errors show a bounded message and correlation reference, never an upstream exception.

Each launch action stores its normalized input and request-scoped idempotency key in session storage before submission. The Pending Operations center shows reconciliation state, attempt count, and the last uncertain error, then lets the author retry with the exact same key/input or abandon it intentionally. Conflict, in-progress, timeout, throttling, gateway, and untyped responses retain the operation; only typed validation, authorization, or missing-resource rejection clears it automatically. A newly created Full Book becomes the active workspace before history refresh begins. Book refreshes use an immutable book ID plus cancellation and generation guards, so late responses from a previously selected book cannot replace the current workspace. Partial failures preserve last known data, identify the failed source in a degraded-state banner, and expose Retry.

ProserAuthor stores no server-side workflow state and runs no worker. On each book selection it rediscovers durable top-level runs and their editorial children, loads one bounded page from `GET /api/books/:bookId/findings`, and then loads the selected run's heartbeat, checkpoints, artifacts, publication gates, review coverage, and immutable revision points. Factory returns an explicit terminal Boolean and monotonic status version; integer version `0` is authoritative, and once a run supplies any integer version the client rejects responses that omit it or move backward. The rolling-deploy fallback includes `publishable_candidate`. One status poll is allowed in flight per run; each next poll starts only after the previous call settles, failures use capped jittered exponential backoff, a successful response resets the delay, and polling pauses while the document is hidden or the browser is offline. An older status version, heartbeat, terminal-state regression, or lower same-heartbeat progress is ignored. Three consecutive failures enter the visible degraded-state banner. Polling returns lightweight resource-version counters; checkpoint history, artifacts, and publication state are fetched only when their counter changes. Active checkpoints contain a bounded summary and references. Full proposal JSON is fetched only when requested and arrives in 16 KiB pages. Phase-specific heartbeat thresholds flag a likely stuck workflow and offer a server-checked recovery action that requeues only when no active job exists. `/quality` and `/continuity` route to this consolidated production desk rather than the retired scan pages.
