The Publish Center now loads formats, review modes and presets from Factory. It
creates revision-bound jobs, exposes failures and exact job recovery, lists retained
history and downloads authenticated immutable artifacts. DOCX import preserves the
original first, previews heading mapping and fidelity losses, and requires explicit
consent before appending chapters. A final-text export does not accept manuscript
changes. Account changes remount publication/import state. The Factory-generated
PDF remains the final layout authority. Full browser restart/import recovery and
native Word exchange acceptance are still release requirements.

The active workspace loads an immutable manifest and at most three canonical scene
bodies. Chapter/book scopes retain neighboring scene documents while mounting one
Canvas editor. Each Canvas render uses a contiguous passage of complete blocks;
passage navigation and scene search retain the complete scene document. Oversized paragraphs and table cells use exact grapheme-safe render slices.
Complete canonical scenes remain in browser memory; the giant-scene server
passage protocol and client activation still need full feature-distribution
acceptance.

scene identities, protected assets and exact review provenance, and save changed

anchor lineage. Undo of a saved boundary operation submits exact owned immutable
scene revisions through Factory's trusted restoration contract; unknown operations

across separate scene editors remain unfinished.

Canvas and semantic editing share stable paragraphs, runs, cells and selection
snapshots. Native composition fences intermediate input; touch selection has an

preserves pending insertion identity through continued typing. Supported text and
formatting revisions retain original/final views. Broader paste/container changes,
physical device accessibility, dictation and orientation acceptance remain required.

Page setup commits book/chapter layout separately from frozen compatibility scene

Comment review shows stale/orphaned anchors with their original quotation and

download and discard; it does not claim that the raw snapshot is a recoverable
canonical commit. Storage failures leave the edit visibly unacknowledged. Raw
hyperlink navigation is guarded inside the maintained core before validation.

## Bounded oversized content

Canvas runtime passages cap ordinary active text at 2,400 UTF-16 units and twelve
complete blocks. A larger paragraph or table uses grapheme-safe text slices; a
table slice opens one exact cell paragraph while the saved document retains every
row, cell, column width and protected object. Slice edits validate the complete
source block and neighbouring identities before merging. Unchanged prefix/suffix
text stays canonical, and selection offsets translate back to the full paragraph.
Paragraph splits, table topology edits and partial-run formatting across slice
boundaries require semantic mode and fail visibly in the bounded Canvas view.

Named paragraph and character styles reference Factory-owned ASCII style IDs with
separate display labels. Both editing surfaces use the shared inheritance
resolver, preserve direct overrides, and avoid persisting inherited visual
defaults. Missing search indexes can be recovered through explicit pages of eight
scene indexes; this never loads manuscript bodies into the browser or mutates a
document revision.

Unsupported native edits keep the editor visibly unacknowledged. Their raw Canvas
value is retained separately from the last valid canonical document, scoped to
the authenticated user/book/story for thirty days. Download or explicitly discard
this quarantine; it is not an acknowledged Factory save. Native merged-cell and
unowned image replacement actions are disabled, and native hyperlink navigation
rejects active URL schemes before canonical validation.

The browser still fetches complete canonical scenes. A book containing one enormous
scene therefore needs a server passage-fetch/operation protocol and separate
worst-case memory/performance acceptance; bounded Canvas painting alone does not
prove bounded full-book fetching.

## Working paragraph layout

Both editing modes expose paragraph indentation, before/after spacing, keep-next
and page-break-before controls. Canvas uses the first logical paragraph's layout
for joined review groups, applies first-line indentation once, and collapses
adjacent spacing to `max(previous after, next before)`. Clipped slices omit spacing
that belongs outside their visible boundaries. Body, table cells and header/footer
stories share the same geometry; Factory PDF remains the final pagination authority.

Wide tables fit the working surface through adapter metadata that preserves their
original column widths and cell IDs. Resizing a visible column maps back to its
source width; viewport changes do not write table dimensions or scene layout.

## Bounded server passage recovery

The passage editing helpers use immutable run hashes, raw UTF-16 offsets and exact
paragraph/cell identities. They emit bounded operations rather than uploading a
whole scene, expand text differences to grapheme boundaries, and reject protected
objects or ambiguous scopes. The user/book/scene journal retains the frozen window,
newer local text and exact original commit/restore request for thirty days.
A scene draft or passage whose save Factory has not confirmed is kept past
thirty days until the writer recovers, downloads or discards it.
Competing tabs and stale acknowledgements cannot replace or delete a newer draft.

Signing out checks this browser for scene and passage drafts. When there are
any, Author lists them and offers to download them as text, remove every Proser
draft and recovery journal from the browser, or keep them for the next
sign-in.
Operation dispatch persists first and recovers the original receipt before an
explicit retry; account changes suppress late acknowledgement callbacks.

These helpers do not activate server passage mode yet. Ordered images/breaks, full
review/comment display, formatting and structural operations, receipt metadata
reconciliation during in-flight typing, navigation/selection and giant-scene
performance still require integration. Bounded Canvas painting and a bounded
backend endpoint alone do not prove complete manuscript editing.

## Image loading policy

The maintained Canvas core checks an application-controlled image policy before
loading document, drag and preview images. Proser requires an exact authenticated
relative asset URL and verified asset/digest metadata. Restricted HTML paste parses
in an inert template, retaining raw image sources as data while removing active
resource attributes before DOM attachment. Unowned external, data and blob images
remain unacknowledged until Factory registers their original bytes. Native request
interception covers batch/history/paste and verifies that owned assets still render.
